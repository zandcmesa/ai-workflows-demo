Three ways in

Same Claude. Different reach.

Claude comes in three apps. The difference is how much of your computer it can see and change. This guide has a full path for the terminal and one for the desktop app. Pick one and the rest of the page follows.

01

Claude on the web

claude.ai, in any browser. The easiest place to start.

  • Great for writing, research and thinking out loud
  • Can't see your files. You upload anything it needs.
  • Ask it how to set up everything else on this page
Easiest
02

Claude desktop app

Everything in a friendly app, including Claude Code in its Code tab.

  • Chat works in folders you choose and with connectors (Gmail, Drive, Wispr Flow)
  • The Code tab gives you Claude Code with buttons, a change viewer and a live preview
  • Nothing to install beyond the app itself
  • Only works while the app is open and online

03

Claude Code, in the terminal

An agent that lives in your project folder.

  • Reads, edits and runs your actual files, not copies
  • Handles git and chains many steps without babysitting
  • Best for building, bulk file work and automation
  • Text only. Learning the permissions takes a day.

0 of 8 done

  1. Homebrew installs command-line tools. Once it's installed, Claude uses it to install whatever a task needs, so you rarely have to think about it again. Open the Terminal app (press ⌘ Space and type "Terminal") and paste:

    /bin/bash -c "$(curl -fsSL https://raw.githubusercontent.com/Homebrew/install/HEAD/install.sh)"

    Watch the end of the output. Homebrew prints a few "Next steps" commands that add brew to your path. Run them too, then close and reopen the terminal.

    Stuck? Paste the error into claude.ai and ask "what does this mean and what do I do next?"

  2. The built-in Terminal works fine. Ghostty is a small upgrade: it's fast, has better fonts, and links are clickable without holding ⌘.

    brew install --cask ghostty

    Or download it from ghostty.org. Use Ghostty for everything from here on.

  3. The ~ (tilde) at the prompt means your home folder, the same one you see in Finder. Make one folder for all your Claude projects, then one folder per project:

    mkdir ~/claude
    cd ~/claude
    mkdir my-first-project
    cd my-first-project

    No spaces in folder names. Spaces confuse the terminal, so use dashes: ai-workflows-demo.

    Press Tab to autocomplete. Type cd my- and press Tab to fill in the rest. Type ls to list what's in the current folder.

  4. With Homebrew installed, it's one line:

    brew install --cask claude-code

    Then, from inside your project folder, start it and sign in with your Claude account (Pro or Max):

    claude

    Homebrew installs don't auto-update. Run brew upgrade claude-code now and then. If you'd rather it update itself, use Anthropic's installer instead: curl -fsSL https://claude.ai/install.sh | bash

    Permission prompts: Claude asks before it runs commands or edits files. Read what it wants to do, then allow it.

  5. Type / inside Claude to see every command. /model switches models:

    /model

    Opus 5.5 is the default and the best all-around pick. Use it for nearly everything.

    Fable 5.1 is for problems that need hours of uninterrupted work. It uses up your plan the fastest.

    Sonnet and Haiku are lighter and quicker, good for simple, repetitive jobs.

  6. Make a free account at github.com. A repository (repo) is just a folder that lives online. You work locally and push changes up. Install GitHub's command-line tool and sign in once:

    brew install gh
    gh auth login

    Create a new repo on GitHub with the same name as your folder, then just tell Claude:

    Prompt

    Connect this project to https://github.com/YOUR-NAME/my-first-project and push a README.

    Press Tab to accept suggestions. Claude often suggests the next step in gray text. Tab fills it in and Enter sends it.

  7. Conductor is a Mac app that runs several Claude sessions at once on the same repo. Each workspace is like a new chat with its own copy of the code. Start a fix in one, an audit in another, and check back later.

    Use it when you're building something: a site, an app, a prototype. For a doc, a deck or brainstorming, plain chat is simpler.

    It asks for a repo first. That's why step 06 comes before this one.

  8. Wispr Flow turns speech into clean text in any app, including your terminal. Spoken prompts tend to be longer and more detailed, which means fewer rounds of clarification.

    Bonus: its meeting notetaker connects to Claude. This guide was built by asking Claude to read the transcript of a recorded walkthrough.

  1. Download the app from claude.ai/download, drag it into your Applications folder, open it and sign in with your Claude account. Claude Code is built in, so you have nothing else to install.

    You'll need a paid plan (Pro, Max, Ultra, Team or Enterprise) for the Code tab. If clicking Code shows an upgrade prompt, that's why.

    Stuck? Ask Claude in the app itself. It can explain any error you see.

  2. Chat is the regular conversation view, and it can now do real work on your files. Click Work in a folder in the message bar to let Claude read from a folder and save finished work back to it. Use it for docs, research, data and anything that ends in a file you read.

    The Code tab is Claude Code with a visual interface. Use it for anything you build: a site, an app, a prototype, a script. It has a change viewer, a live browser preview and parallel sessions.

    See separate "Chat" and "Cowork" options? Anthropic is merging them into one and rolling the change out in stages. Until it reaches you, use Cowork for work on your files.

    Guided setup: start a new conversation and type the command below. Claude asks about your role and suggests tools to connect.

    /setup-claude

  3. Open Finder and press ⌘ ⇧ H to go to your home folder. Choose File → New Folder, name it claude, then make a folder inside it for your first project: my-first-project.

    No spaces in folder names. Use dashes: ai-workflows-demo. Lots of developer tools still trip over spaces.

    One folder per project. Claude treats the folder you open as its whole world, so keep each project's files together.

  4. Click the Code tab. In the row under the prompt box, click the first control (the environment) and choose the top Local entry. Click the folder control next to it, choose Open folder… and pick my-first-project. Then give Claude a first job:

    Prompt

    Create a README.md that explains what this project is for and how it's organized. Ask me any questions you have.

    Review what changed. When Claude edits files, an indicator like +12 -1 appears. Click it to see every change, line by line, and leave comments that Claude will act on.

    Steer at any time. Type a correction and press Enter while Claude works, or press Esc to stop it.

  5. Model picker (⌘ ⇧ I): Opus 5.5 is the default and the best all-around pick. Fable 5.1 is for problems that need hours of work and uses up your plan the fastest. Sonnet and Haiku are lighter and quicker.

    Permission mode (⌘ ⇧ M) sets how often Claude checks with you:

    Manual: approve every change. A good way to start and see how Claude works.

    Accept edits: file changes go through, but Claude still asks before running commands.

    Plan: Claude proposes an approach without changing anything. Use it before big jobs.

    Auto: Claude keeps going and a safety check blocks risky actions. Use it once you trust the flow.

  6. Make a free account at github.com and create a new, empty repository (an online folder) with the same name as your project folder. Then, in your Code session, let Claude choose the simplest setup for your Mac:

    Prompt

    I'm new to git and GitHub. Connect this folder to https://github.com/YOUR-NAME/my-first-project and push the README. Check what's already installed, pick the simplest option for a beginner, and walk me through any one-time sign-in step in plain language. Ask me any questions you have.

    Signing in is a one-time step. Claude may open a GitHub page in your browser or show you a short code to enter there. Never paste a password into the chat.

    If your Mac asks to install "command line developer tools," click Install. That's how Macs add git.

  7. Conductor is a Mac app that runs several Claude sessions at once on the same repo, each with its own copy of the code. It's visual too, so it fits this path: add your repo, click to start a workspace, type a task, then start another.

    Use it when you're building something: a site, an app, a prototype. For a doc, a deck or brainstorming, plain chat is simpler.

    Inside the Claude app, + New (⌘ N) in the Code tab also starts a parallel session. Turn on Worktree to give it its own copy of the project.

  8. Open Customize → Connectors in the sidebar to link Gmail, Google Drive, Calendar and more. Claude can then read and act on them in both Chat and the Code tab.

    Wispr Flow turns speech into clean text in any app. Spoken prompts tend to be longer and more detailed, which means fewer rounds of clarification. Its connector also lets Claude read your meeting notes.

    This guide was built that way: Claude read the Wispr Flow transcript of a recorded walkthrough through the connector.

Workflows

Four ways to actually use it.

Shown for the desktop app: Chat for research and data, the Code tab for anything you build. Each workflow is a short sequence of plain-English prompts. Copy them, swap in your details, and end with "Ask me any questions you have." so Claude checks with you before it guesses.

Research in, decisions out.

Claude Code reads every file in a folder at once, which makes it a fast research partner. Drop in interview transcripts, survey exports or screenshots and ask questions across all of them.

  • Put source files in a folder like research/
  • Wispr Flow meeting notes work as transcripts
  • Ask for quotes so you can check its work

  1. Synthesize the research, in Chat

    Start a new conversation, click Work in a folder and choose your research folder. Your files never need uploading.

    Read every file in this folder. Pull out the top 5 user pain points, ranked by how often they come up, with 2 direct quotes each and the file each quote came from.

  2. Pressure-test the plan

    Install the /grill-me skill once from the Code tab (see Skills), then have it question you one decision at a time.

    /grill-me I want to add a self-serve onboarding flow for new customers. Here's my rough plan: [plan]

    Open a Code session on the same folder. The prototype opens right in the Browser pane, so you can click through it and point at what to change.

Ask your spreadsheet anything.

Put a CSV or Excel export in the project folder. Claude writes and runs the analysis code for you, so the numbers come from the actual data, not from a guess.

Start a task. Start another.

In Conductor, each workspace runs its own Claude session on the same repo, so separate jobs don't step on each other. Here are the two tasks from the original walkthrough, run side by side on a live church website.

Prefer to stay in the Claude app? In the Code tab, + New (⌘ N) with Worktree turned on does the same job. To watch two sessions side by side, hold ⌥ and click a session in the sidebar.

  • One task per workspace
  • No need to name the project, the repo is the context
  • Review each change before you merge it

  1. Workspace A: fix a bug you can see

    When I load the site, the fonts are slow and the text jumps when the real font swaps in. Can you help me make the loading smoother? Ask me any questions you have.

    Claude's fix: host the three font files on the site itself (109 KB total), preload them, size the fallback fonts to match, and hold the hero animation for up to about 800 ms.

  2. Workspace B: audit, meanwhile

    Do a security audit of this website. Poke holes in everything and tell me how to best secure it against vulnerabilities. Ask me any questions you have.

  3. Answer its questions, then review

    Each workspace checks in when it needs a decision ("Are you OK hosting the font files yourself?"). Answer, let it finish, and look over the changes before they ship.

          Saving tokens
          
Why one task per session matters.

          
Every time you send a message, Claude re-reads the whole conversation so far. Message 20 costs far more than message 2. Long, wandering sessions are what use up your plan. Keeping each session short is what keeps it in check.

Illustrative model: each message adds about 2,000 tokens of context, and every message re-sends everything before it. Real numbers vary with files, tool output and caching, but the shape holds. Each block is one task.

        

      

      

        
/clear
Finished a task? Clear the conversation before starting the next one.

        
+ New · ⌘N
Finished a task? Start a new session (or new chat) for the next one instead of continuing the old one.

        
/compact
Need to keep going on the same task? Compact summarizes the history so it's lighter to carry.

        
/context
Shows how full the current session is and what's taking up the space.

        
Usage ring
The ring under the prompt box shows your plan usage. /context shows how full this session is.

        
Brief well
Put the goal, constraints and examples in the first message. Dictating it with Wispr Flow makes long briefs painless.
